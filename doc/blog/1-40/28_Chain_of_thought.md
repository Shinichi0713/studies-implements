
論文読むと推論モデルとそうでないモデルという言い方で違いが出ているのを見ます。
この違いはステップバイステップの思考を行ったか行っていないか。
そして、このステップバイステップの思考を制御しているものが思考トークン（Thinking Tokens）と呼ばれるものです。
本日はそんな思考トークンと思考トークンを用いてステップバイステップの思考を行う挙動について説明します。

## 思考トークンとは

**思考トークン** は、LLMが**内部の推論プロセスを言語化するために使う、ユーザーには見えないトークン**です。  
LLMは「次トークン予測器」であり、**どんなトークン列も「言語として生成できる」** ため、  
- まず**内部で推論ステップ（思考トークン列）** を生成し、  
- その後に**最終回答トークン**を生成する、という形で「考えている」ように振る舞えます。

### 1. なぜ思考トークンで推論できるのか

- LLMは **「与えられたトークン列の次に来るトークンを予測する」** モデルです。  
- 複雑な問題では、  
  - **いきなり結論を出すよりも、ステップを踏んでから結論を出す方が「もっともらしい」** ことが多いため、  
  - モデルは**内部で推論ステップ（思考トークン）を生成し、その後に結論を出す**方が、統計的に正解に近くなります。  
- つまり、**「推論のステップ」も「結論」も、すべてトークン列として扱える**ため、思考トークンで推論が可能になります。


### 2. RLVRと推論時スケーリング：思考トークンを「鍛える」

- **RLVR（Reinforcement Learning from Verifiable Rewards）** では、  
  - 数学・コードなど「正解が自動検証できるタスク」で報酬最大化の強化学習を行い、  
  - **思考トークン列＋結論トークン**を生成する過程で、  
  - **「どういう思考トークン列を生成すれば正解に辿り着きやすいか」** を学習します[Karpathy: 2025 LLM Year in Review](https://karpathy.bearblog.dev/year-in-review-2025/)[Sebastian Raschka: State of LLMs 2025](https://magazine.sebastianraschka.com/p/state-of-llms-2025)。  
- **推論時スケーリング**では、  
  - **思考トークンの長さ（考える時間）を増やすほど能力が上がる**というスケーリング則が確立されており、  
  - OpenAI o3やDeepSeek R1などは、**長い思考トークン列を許容するモード**を持ちます[Karpathy: 2025 LLM Year in Review](https://karpathy.bearblog.dev/year-in-review-2025/)。


### 3. 思考トークンを使ったスコアリング（Reasoning’s Razor）

- Appleの「Reasoning’s Razor」では、  
  - **思考トークンのlogits（確率分布）**を解析することで、  
  - **モデルの確信度や不確実性を推定**しています[Apple Machine Learning Research](https://machinelearning.apple.com/research/reasoning-razor)。  
- 自己申告の確信度より、**思考トークンベースのスコアリングの方が有効**であり、  
  - 特に低FPR領域（誤検出を1%以下に抑える設定）で、Recallを維持するのに役立ちました。

## LLMをどのように制御しているか

**思考トークン**は、LLMの**内部推論プロセスを言語化したトークン列**であり、  
これを **「見えない形で生成させる」ことで、LLMの推論能力や確信度を制御**します。

### 1. 思考トークンの基本的な仕組み

- LLMは通常、**入力トークン → 出力トークン**を直接生成します。
- 思考トークンを使う場合：
  - **内部で「推論ステップ（思考トークン列）」を生成**し、
  - その後に**ユーザーに見える出力トークン**を生成します。
- このとき、
  - 思考トークンは**ユーザーには見えない**（APIでは内部的に消費される）。
  - しかし、**モデルの内部状態やlogits（確率分布）には反映**されます。


### 2. APIレベルでの制御方法（例：Anthropic Claude）

AnthropicのClaude APIでは、**Extended Thinking / Adaptive Thinking**という機能で思考トークンを制御しています[Claude API Docs: Extended Thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)。

__（1）Extended Thinking（拡張思考）__

- **`extended_thinking` パラメータ**を有効にすると、
  - モデルは**内部で長い思考トークン列を生成**し、
  - その後、**要約された回答**を出力します。
- 特徴：
  - **思考トークンはユーザーには見えない**が、推論の質が向上。
  - 数学・コード・複雑な論理問題などで**精度が向上**します。

__（2）Adaptive Thinking（適応的思考）__

- **`adaptive_thinking` パラメータ**を有効にすると、
  - モデルが**タスクの難易度に応じて思考トークンの長さを自動調整**します。
- 例：
  - 簡単な質問：短い思考トークンで高速回答。
  - 難しい質問：長い思考トークンで深く推論。

__（3）max_tokensによる制御__

- **`max_tokens`**パラメータで、
  - **思考トークン＋出力トークンの合計上限**を設定できます。
- Vellumの解説では、
  - **思考トークン専用のmax_tokensを調整**することで、
    - 「深い推論（高精度）」か「高速・低コスト」かを制御できると説明されています[Vellum: Thinking Tokens](https://vellum.ai/llm-parameters/thinking-tokens)。

### 3. モデル内部での制御（RLVR・推論時スケーリング）

__（1）RLVR（Reinforcement Learning from Verifiable Rewards）__

- 数学・コードなど**正解が自動検証できるタスク**で、
  - **思考トークン列＋結論トークン**を生成させ、
  - 正解なら報酬、不正解なら罰という**強化学習**を行います[Karpathy: 2025 LLM Year in Review](https://karpathy.bearblog.dev/year-in-review-2025/)。
- これにより、
  - **「どういう思考トークン列を生成すれば正解に辿り着きやすいか」**という推論戦略が学習されます。

__（2）推論時スケーリング（Test-time Scaling）__

- Karpathyは、**「考える時間（思考トークンの長さ）を増やすほど能力が上がる」** というスケーリング則を指摘しています[Karpathy: 2025 LLM Year in Review](https://karpathy.bearblog.dev/year-in-review-2025/)。
- 具体的には、
  - **思考トークンの長さ（推論トレースの長さ）** を増やすことで、
  - 複雑なタスクの正答率が向上します。
- 例：OpenAI o3、DeepSeek R1は、**長い思考トークン列を許容するモード**を持ちます。


### 4. スコアリング・確信度推定での制御（Reasoning’s Razor）

Appleの「Reasoning’s Razor」では、**思考トークンのlogits（確率分布）** を解析することで、**モデルの確信度を推定**しています[Apple Machine Learning Research](https://machinelearning.apple.com/research/reasoning-razor)。

- モデルは、
  - 思考トークン列を生成し、
  - その後に最終回答トークンを生成します。
- このとき、
  - **思考トークンのlogitsが「シャープ（確信度高）」か「フラット（不確実）」か**を観察することで、
  - **「モデルがどれだけ確信しているか」を推定**できます。
- 結果：
  - **自己申告の確信度より、思考トークンベースのスコアリングの方が有効**でした。
  - 特に低FPR領域（誤検出を1%以下に抑える設定）で、Recallを維持するのに役立ちました。

→ **思考トークンは、「推論の質」や「確信度」を評価するための情報源にもなります。**

## ステップバイステップの制御


**LLMにステップを生成してから思考を開始する**部分は、**基本的には「同じLLMの中で」行われています**。  
別のLLMが前に立ってオーケストレーションするケースもありますが、**「思考トークン」という文脈では、主に「単一LLMの内部プロセス」** です。


### 1. 単一LLM内での「思考トークン」生成

- LLMは**自己回帰的にトークンを生成**します。
  - 入力トークン列 → 1つ目の出力トークン → それをまた入力に加えて2つ目…という繰り返し。
- **思考トークン**は、
  - **「内部の推論ステップ（理由・計算過程）」を言語トークンとして生成する部分**です。
  - ユーザーには見えず、**同じLLMが「まず考えてから答える」** という形で処理します。
- 例：Anthropic ClaudeのExtended Thinking[Claude API Docs: Extended Thinking](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)：
  - 同じClaudeモデルが、
    - 内部で**長い思考トークン列（自然言語の推論ステップ）** を生成し、
    - その後、**要約された回答トークン**を生成します。
  - これは**単一モデル内のプロセス**です。


### 2. オーケストレーション（別LLMが前に立つケース）

一方で、**「LLMエージェント」や「マルチステップ推論システム」** では、**別のLLMやオーケストレータが前に立つ**ことがあります。

__（1）LLM App Layer（Cursorなど）__

- Karpathyの「2025 LLM Year in Review」では、**LLM App Layer（Cursorなど）** が紹介されています[Karpathy: 2025 LLM Year in Review](https://karpathy.bearblog.dev/year-in-review-2025/)。
- ここでは、
  - **アプリケーション層のLLM（オーケストレータ）** が、
    - どのモデルを呼ぶか、
    - どのようにプロンプトを組み立てるか、
    - どのタイミングでツールを呼ぶか、
    を制御します。
- ただし、**「思考トークン」そのものは、各モデル内部で生成**されます。

__（2）マルチエージェント・マルチモデル__

- 複数のLLMエージェントが協調するシステムでは、
  - **エージェントAが「計画」を立て、エージェントBが「実行」する**といった役割分担が行われます。
- この場合も、
  - **各エージェント内部では思考トークンが生成**され、
  - オーケストレータは「どのエージェントに何をさせるか」を制御します。


### 3. 「思考トークン」と「オーケストレーション」の違い

- **思考トークン**：
  - **単一LLM内部で、推論ステップを言語トークンとして生成するプロセス**。
  - ユーザーには見えないが、**同じモデルが「考えてから答える」** 。
- **オーケストレーション**：
  - **別のLLMやアプリケーション層が、複数のモデル・ツールを組み合わせてタスクを遂行する**プロセス。
  - 各モデル内部では思考トークンが生成されるが、**全体のフローはオーケストレータが制御**。


### 4. まとめ

- **「ステップを生成してから思考を開始する」部分は、基本的には「同じLLMの中で」行われています。**
  - LLMは**自己回帰的にトークンを生成**し、
  - **思考トークン（推論ステップ）→ 結論トークン**という順で内部処理します。
- **オーケストレーション**は、
  - 別のLLMやアプリケーション層が**複数のモデル・ツールを組み合わせる**際に使われますが、
  - **「思考トークン」そのものは各モデル内部で生成**されます。

**「思考トークン」は単一LLMの内部プロセス、オーケストレーションは複数モデル・ツールの連携**という役割分担になっています。

- 複雑な問題では、いきなり結論を出すよりも、ステップを踏んでから結論を出す方が「もっともらしい」 ことが多いため、モデルは内部で推論ステップ（思考トークン列）を生成し、その後に結論トークンを生成します。
- LLMは「与えられたトークン列の次に来るトークンを予測する」 モデルであり、「推論のステップ」も「結論」も、すべてトークン列として扱えるため、思考トークンで推論が可能になります。
- 思考トークンは、LLMの内部推論プロセスを言語化したトークン列であり、これを 「見えない形で生成させる」ことで、LLMの推論能力や確信度を制御します。
- 思考トークンは、「内部の推論ステップ（理由・計算過程）」を言語トークンとして生成する部分です。ユーザーには見えず、 同じLLMが「まず考えてから答える」という形で処理します。
